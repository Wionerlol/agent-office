快速启动

生产式单端口启动

uv sync
cd frontend
npm install
npm run build
cd ..
uv run agent-office

打开 http://127.0.0.1:8000。后端同时提供打包后的 UI、REST 接口和 WebSocket。

前后端开发模式

# 终端 1
uv run uvicorn backend.main:app --reload

# 终端 2
cd frontend
npm run dev

开发 UI 位于 http://127.0.0.1:5173，Vite 会代理 /api、/health 和 /ws。

无真实 Agent 也能体验：访问 /?demo=true，页面会生成 4 个模拟角色并每 5–10 秒随机切换状态。

接入真实 Agent

保持 Agent Office 服务运行，再用 office-run 启动 Agent。Wrapper 会注册 PID、Provider、仓库、分支和 worktree，并记录完整退出生命周期。

uv run office-run codex \
  --name Backend \
  --role Backend \
  --task "Implement authentication API" \
  --repo /home/user/projects/demo

Provider 后面的未知参数会原样传给真实命令，例如：

uv run office-run claude --name Reviewer --repo /path/to/repo --dangerously-skip-permissions
uv run office-run opencode --name UI-Agent --role Frontend
uv run office-run my-agent --name Custom --server http://127.0.0.1:8000/api/events

若服务暂时不可达，Wrapper 会把事件回退写入 runtime/events.jsonl；下次服务启动时会恢复该历史。

界面操作

  • 办公室：角色沿 A* 路径移动到当前状态对应区域；点击角色打开详情。
  • 详情面板：查看 Provider、角色、个性、任务、PID、分支、worktree、工具、改动文件和最近事件。
  • Project：配置多个仓库后，选择单个仓库或查看全部；worktree Agent 会跟随对应项目筛选。
  • Replay history：加载 JSONL 历史，支持暂停、继续和 1×/2×/5×速度；点 Live 返回实时快照。
  • Debug controls：生成/删除 Agent、随机化状态、制造错误和重置。在线模式通过后端事件执行，模拟模式只修改本地状态。
  • 连接状态：connected、reconnecting、disconnected、simulation 或 replay。

配置

编辑 config/office.yaml。相对路径按仓库根目录解析。

project:
  name: agent-office
  path: .
projects:
  - name: agent-office
    path: .
  - name: another-repo
    path: ../another-repo
observer:
  enabled: true
  idle_timeout: 30
  scan_interval: 1
  tool_scan_interval: 0.1
server:
  host: 127.0.0.1
  port: 8000
office:
  desks: 8
frontend:
  port: 5173
runtime_path: runtime/events.jsonl

用 AGENT_OFFICE_CONFIG 指向其他配置，用 AGENT_OFFICE_LOG_LEVEL=DEBUG 开启详细日志。

安全提示：接口没有身份认证。默认只绑定 127.0.0.1；除非已放在受保护的反向代理之后，否则不要暴露到公网。

HTTP / WebSocket

接口说明
GET /health服务健康状态
GET /api/agents当前活动 Agent
GET /api/agents/{id}完整 Agent 详情
GET /api/project当前项目与分支
GET /api/projects已配置项目列表
GET /api/history历史事件；支持 agent_id 和 limit
GET /api/config前端可安全读取的办公室配置
POST /api/events提交标准 AgentEvent
WS /ws首次快照与后续增量

提交事件示例

curl -X POST http://127.0.0.1:8000/api/events \
  -H 'Content-Type: application/json' \
  -d '{
    "type":"agent.state_changed",
    "agent_id":"backend",
    "timestamp":"2026-09-04T16:00:00+08:00",
    "payload":{"from":"coding","to":"testing"}
  }'

WebSocket 首帧为 {"type":"snapshot","agents":[]}，随后推送 agent.started、agent.updated 和 agent.stopped。

架构

Process / Git / FS / Wrapper→Provider Adapter→AgentEvent→OfficeRuntime→REST / WebSocket / JSONL→React + PixiJS

OfficeRuntime.apply(event) 是状态变更的唯一入口。前端不判断 Codex 或 Claude 的私有行为，只理解 Agent、AgentState 和 AgentEvent。

故障排查

页面显示 disconnected 或 reconnecting

确认后端位于 8000 端口，检查 curl http://127.0.0.1:8000/health。开发模式还需确认 Vite 代理配置未改变。

办公室没有出现 Agent

用 office-run 启动进程，或确认进程名是 Codex/Claude/OpenCode。若正在筛选 Project，检查 Agent 的 repository/worktree 是否匹配。

Agent 很快进入 idle

提高 observer.idle_timeout；任何标准事件或文件改动都会刷新最后活动时间。

历史回放为空

检查 runtime_path 和 JSONL 文件权限。通过 HTTP 成功提交或 Wrapper 回退写入的事件都会出现在这里。

修改前端后首页未更新

生产式启动读取 frontend/dist；重新运行 cd frontend && npm run build，或使用 Vite 开发服务器。
